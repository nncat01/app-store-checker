# Реестр приложений App Store

Автоматически обновляемый список приложений из App Store: название, App ID,
Bundle ID, разработчик, версия, размер, поддержка iOS/iPadOS и доступность
по 29 регионам. Обновляется 3 раза в сутки через GitHub Actions.

## Структура

- **`links.txt`** — список ссылок на App Store (или голых App ID), по одной
  на строку. Строки с `#` — комментарии, игнорируются.
- **`update_apps.py`** — скрипт, который читает `links.txt`, запрашивает
  данные через открытый iTunes Lookup API и пишет/обновляет `apps.csv`.
- **`apps.csv`** — сам реестр. Появится после первого запуска. Смотреть
  можно прямо на GitHub, без скачивания — вкладка с файлом рендерит CSV
  как таблицу.
- **`.github/workflows/update-apps.yml`** — расписание автозапуска.

## Как включить автообновление

1. Запушь этот репозиторий на GitHub (публичный — тогда Actions бесплатны
   без ограничений; для приватного есть бесплатный лимit минут в месяц).
2. Впиши свои приложения в `links.txt`.
3. Первый запуск можно сделать вручную: вкладка **Actions** → workflow
   **Update app registry** → **Run workflow**. Дальше пойдёт по расписанию
   (06:00 / 14:00 / 22:00 UTC).
4. Проверь, что во вкладке **Settings → Actions → General → Workflow
   permissions** включено **Read and write permissions** — иначе workflow
   не сможет закоммитить обновлённый `apps.csv` обратно в репозиторий.

## Как это работает с датами пропажи

Когда приложение перестаёт быть доступно в каком-то регионе, рядом с "✗"
фиксируется дата в скобках — `✗ (24.08.2026)`. Эта дата ставится один раз,
при первом обнаружении, и дальше не переписывается, пока регион снова не
станет доступен (тогда отметка сбрасывается обратно на "✓").

Важная оговорка: если приложение уже отсутствовало в регионе до самого
первого запуска скрипта, дата будет означать «когда мы это заметили», а не
реальную историческую дату удаления — Apple эту информацию нигде не
публикует.

## Локальный запуск

```bash
pip install -r requirements.txt
python update_apps.py                 # links.txt -> apps.csv
python update_apps.py --no-regions    # без проверки регионов (быстрее)
```

## Заметка про время выполнения

Полная проверка одного приложения по всем 29 регионам занимает ~1.7 минуты
(из-за паузы между запросами — так iTunes API не банит по IP). При большом
списке приложений в `links.txt` весь прогон может занять ощутимое время —
учитывай это при большом количестве записей.
